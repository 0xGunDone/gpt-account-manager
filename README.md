# GPT Account Manager

Локальный менеджер ChatGPT-аккаунтов для macOS 14 и новее. Используйте его для аккаунтов, которыми вы вправе управлять.

## Установка и обновление

Для сборки нужны macOS 14 или новее, Git, Swift 6 (Xcode 16 или новее либо совместимые Command Line Tools) и Node.js 20+ с npm. При первом запуске npm загрузит зависимости из реестра.

```bash
git clone https://github.com/0xGunDone/gpt-account-manager.git
cd gpt-account-manager
./run.sh
```

После первой сборки открывайте `dist/GPT Account Manager.app` из Finder или Dock. Пока приложение закрыто, при новом запуске оно проверяет `main` публичного репозитория. Если есть обновление, приложение собирает его и перезапускается. Прежняя сборка открывается, если GitHub недоступен, в клоне есть локальные правки, история разошлась или обновление собрать не удалось.

Оставьте `.app` в папке `dist` внутри клона с веткой `main`, отслеживающей `origin/main`. Обновление из приложения работает для сборки из чистого клона этого репозитория. Для прежней сборки выполните `./run.sh` один раз. Этот скрипт по-прежнему подтягивает изменения из настроенной upstream-ветки перед сборкой.

Для сборки из текущих файлов без проверки Git используйте `./script/build_and_run.sh`.

### Пароль для регистрации и смены доступов

Для этих операций задайте `GPTAM_NEW_PASSWORD` в окружении запуска. В стандартной оболочке macOS можно ввести значение скрыто:

```zsh
read -rs 'GPTAM_NEW_PASSWORD?Новый пароль: '
printf '\n'
export GPTAM_NEW_PASSWORD
./run.sh
unset GPTAM_NEW_PASSWORD
```

Без этой настройки доступны импорт, проверка и смена только 2FA. Уже начатая операция использует сохранённый ожидающий пароль, если он был записан.

### Ключ доступа Safari

Кнопка «Создать ключ доступа в Safari» открывает обычное окно Safari. Для этой функции нужны Safari 18.4 или новее, локальная сборка с сертификатом Apple Development и включённое расширение GPT Account Manager с доступом к `chatgpt.com`. Приложение сверяет уже открытый в Safari аккаунт. При отсутствии сессии оно открывает страницу входа. Создание ключа подтверждается вручную в Safari.

## Формат

Одна строка соответствует одному аккаунту. Формат экспорта и редактирования карточки:

```text
LOGIN|PASS|2FA
```

Пароль может содержать `|`: разделителями считаются первый и последний символы `|`. 2FA — Base32-секрет приложения-аутентификатора.

Кнопки `Добавить текстом` и `Импорт` открывают предварительный просмотр с выбором разделителя: `|`, `:`, `;`, `,`, табуляция или свой текст, например `::` и `----`. Автоматический режим распознаёт стандартные разделители отдельно в каждой строке, поэтому их можно смешивать в одном файле. Это построчный текст, не CSV с правилами кавычек.

Для выбранного разделителя используются первое и последнее вхождения. Пароль между ними сохраняется точно, включая пробелы и дополнительные разделители. Свой разделитель не может быть пустым или содержать перенос строки. Предпросмотр показывает распознанные аккаунты, дубликаты и номера ошибочных строк; неподходящие строки не добавляются.

При повторном импорте существующего email пароль обновляется, а сохранённый 2FA остаётся прежним. Для намеренной замены ключа используйте поле `LOGIN|PASS|2FA` в карточке аккаунта и `Сохранить`. Итог импорта показывает, у скольких аккаунтов сохранён текущий 2FA.

### Внешняя почта для кодов входа

Вставьте блок в «Добавить текстом» или укажите почту и ссылку API в разделе «Внешняя почта для входа» в карточке аккаунта.

```text
Email: account+alias@example.com
Password: example-password
2FA: JBSWY3DPEHPK3PXP
Mailbox email: account+alias@example.com
Ссылка для кода с почты: https://mail.example.com/api/code?key=example
```

При входе в ChatGPT и импорте в CodexAcc приложение сначала выбирает «Продолжить с паролем», если эта кнопка доступна. Когда OpenAI запрашивает код из письма, приложение проверяет адрес на форме и ждёт новый код из API. Поддерживается HTTPS API с JSON `{"success":true,"code":"012345"}` и ответом `{"success":false,"code":"no_code"}`, когда письма ещё нет. Если свежесть кода или адрес подтвердить нельзя, приложение оставляет форму для ручного ввода.

Ссылка API хранится в локальной записи аккаунта и используется только для запроса к почтовому сервису. Для регистрации и смены почты действует прежний сценарий Mail.ru.

## Вход в CodexAcc через OAuth

«Импорт в CodexAcc» в карточке аккаунта получает ссылку и передаёт результат автоматически. Сохранённая сессия, пароль и действующий 2FA используются для входа; обычное подтверждение Codex поддерживается автоматически, а дополнительные проверки OpenAI остаются в открытом браузере. Аккаунт добавляется только при совпадении выбранного email, текущий аккаунт Codex не переключается. Уже добавленные адреса пропускаются. «Импорт группы в CodexAcc» делает то же строго по одному; ручное действие или ошибка останавливает очередь до «Продолжить импорт».

Для прямого импорта нужна обновлённая локальная сборка CodexAcc с поддержкой GPT Account Manager. Оба приложения работают на этом Mac; вручную вставлять ссылки и callback не нужно.

1. Выберите аккаунт и нажмите `Проверить`, чтобы войти в ChatGPT. Обычная проверка использует отдельную сохраняемую сессию каждого аккаунта.
2. В CodexAcc начните добавление аккаунта через OAuth и скопируйте ссылку входа. Оставьте CodexAcc в ожидании результата.
3. В карточке выбранного аккаунта вставьте ссылку в поле входа и нажмите `Открыть в сессии`.
4. Подтвердите доступ на странице OpenAI. Результат вернётся в CodexAcc через адрес `redirect_uri` из ссылки, включая `http://localhost:порт/auth/callback`.

Ссылка не записывается в базу. Перед действием программа проверяет сохранённую сессию и выбранный аккаунт; повторный вход запускается при отсутствии или истечении сессии. Во время проверки или восстановления 2FA открытие OAuth недоступно. Проверка нового пароля или 2FA использует отдельную чистую сессию, после успешного доказательства вход сохраняется в профиле аккаунта. Автоматический выход из всех сеансов после смены 2FA отключён.

## Внешние ссылки и ручной callback

Поле входа принимает полные HTTP/HTTPS-ссылки, включая внешние страницы входа и OAuth с удалённым HTTP callback. Режим «Вернуть в приложение» сохраняет прежний возврат в CodexAcc. В режиме «Скопировать callback» браузер перехватывает точный callback из OAuth-ссылки, не отправляя его на сервер возврата.

Над браузером есть редактируемая адресная строка, «Перейти» и «Копировать URL». Адрес callback остаётся доступен даже при недоступном localhost. Переходы через строку отключены во время операций и восстановления доступов. Ручная навигация не разрешает автоматическую отправку паролей на сторонние сайты.

## Смена доступов

«Сменить доступы» в карточке аккаунта и группе предлагает три режима: «Пароль», «2FA», «Пароль и 2FA». Для нового пароля используется настройка запуска `GPTAM_NEW_PASSWORD`. В совместном режиме сначала меняется и проверяется пароль, затем запускается существующий цикл 2FA. Режим «2FA» работает как прежде.

«Сменить почту группы» назначает каждому доступному аккаунту отдельный свободный адрес из базы и выполняет смену строго по одному. После паузы можно продолжить очередь или снять незапущенные аккаунты. При смене пароля и подтверждении личности коды автоматически читаются из подключённого Mail.ru с проверкой получателя. Подробнее: [docs/GROUP_EMAIL_AND_PASSWORD.md](docs/GROUP_EMAIL_AND_PASSWORD.md).

Новый пароль становится основным только после чистого проверочного входа в тот же аккаунт. До этого сохраняются старый и ожидающий пароль, а операция может продолжиться после перезапуска. Если форму пришлось заполнить вручную, используйте «Пароль уже изменён вручную — проверить». Если отправка нового пароля не завершилась, «Открыть смену пароля заново» возвращает к смене с сохранённым старым паролем, сохраняя оба значения до проверки.

OpenAI может потребовать код из почты именно при смене пароля. Без доступа к почте этот шаг завершить нельзя. До отправки нового пароля действие можно остановить, затем отдельно запустить только 2FA. После отправки ожидающий пароль сохраняется до подтверждённого входа.

## Алиасы и смена email

«База почт» хранит ваши iCloud-алиасы со статусами «Свободен», «В работе», «Использован». Добавляйте адреса по одному на строку. «Почта Mail.ru» открывает отдельное встроенное окно. Укажите свой адрес, войдите вручную и сохраните вход. Сессия почты хранится отдельно от сессий ChatGPT и восстанавливается между запусками. Mail.ru может завершить сессию на своей стороне — тогда потребуется повторный вход.

В карточке аккаунта выберите свободный алиас и «Сменить email». Приложение резервирует адрес, проверяет исходный аккаунт и доступ к почте, запрашивает код и ищет новое письмо для точного адресата. Старые письма, другой алиас, неоднозначные коды и неподтверждённые отправители не подходят. Проверка чтения почты доступна отдельной кнопкой в почтовом окне.

Сохранённый email меняется только после входа с новым адресом и совпадения постоянного идентификатора пользователя OpenAI. Проверочный вход поддерживает как страницу auth.openai.com, так и окно «Войти или зарегистрироваться» на главной ChatGPT; незагруженная страница повторяется, уже открытая форма не сбрасывается. Пароль, 2FA, группа, тег и локальный ID сохраняются. Успешно использованный алиас больше не попадает в свободную очередь.

До запроса кода резерв можно отменить. После начала запроса/подтверждения остановка сохраняет оба адреса и этап; алиас не освобождается автоматически. «Продолжить смену email» возобновляет операцию. «Проверить новый email» проверяет уже подтверждённую вручную смену. Если проверочный вход завис, «Новый вход» создаёт отдельную чистую сессию и повторяет вход с новым адресом; повторная смена email и повторная отправка почтового кода не запускаются. Кнопка доступна на этапе проверки после остановки текущей попытки. «Вернуться к подтверждению email» показывает исходную форму, если проверочный вход пока не прошёл. После перезапуска приложение не отправляет повторный запрос смены вслепую.

Если выбранный алиас занят другим аккаунтом, «Заменить email для смены» позволяет выбрать свободный адрес из базы. После начала запроса приложение сначала проверяет прежний email и идентификатор исходного аккаунта. Занятый алиас остаётся использованным; новый резерв получает отдельную операцию без старых кодов. Замена сохраняет текущие доступы и не запускает новую смену автоматически — затем нажмите «Продолжить смену email».

Чтение проверено на лёгкой версии Mail.ru и письме ChatGPT через iCloud «Скрыть e-mail»: программа проверяет служебные заголовки Mail.ru и подписанный iCloud адрес первоначального отправителя, адрес алиаса и ящик пересылки. Для операции принимаются только письма, отсутствовавшие до запроса кода, с подходящим временем и точным адресатом. Неизвестная разметка останавливает автосбор с объяснением вместо выбора случайного кода. Кнопка «Проверить чтение» позволяет проверить открытое письмо без отправки кода.

## Выбор и группы

- обычный клик выбирает один аккаунт;
- `⌘`-клик добавляет или убирает аккаунт из выбора;
- `⇧`-клик выбирает диапазон строк;
- выбранные аккаунты можно перетащить на группу или на `Без группы`;
- перед переносом приложение показывает подтверждение, а запись выполняется одной атомарной операцией.

## Важно

- Логины, пароли и 2FA-ключи намеренно хранятся без шифрования в `~/Library/Application Support/GPT Account Manager/accounts.json`.
- `Проверить все` обрабатывает аккаунты строго последовательно.
- `Проверить группу` в карточке группы проверяет только её аккаунты, строго по одному; доступно и для `Без группы`. При ручном действии очередь ждёт, `Продолжить` возобновляет тот же аккаунт и оставшуюся часть выбранной группы.
- После успешной проверки программа сохраняет `accessToken` из сессии с совпадающей почтой. Это работает для `Проверить`, `Проверить группу`, `Проверить все` и продолжения проверки. Готовые аккаунты `new-novoreg` автоматически попадают в `new-novoreg-access-tokens.txt` рядом с `accounts.json` в формате `почта|accessToken`; если токен недоступен, прежний кэш сохраняется и программа сообщает об этом.
- «Экспорт токенов» в группе или панели инструментов сохраняет выбранные готовые аккаунты в текст, CPA JSON, sub2api JSON или Cockpit JSON. Для нескольких аккаунтов CPA создаётся новая папка с отдельным JSON на каждый аккаунт; один аккаунт сохраняется обычным JSON-файлом. Предпросмотр сообщает о пропусках и истечении срока; пароли, TOTP и cookies не включаются. JSON содержит реальные access tokens без синтетических ID/refresh tokens. Наличие JSON не гарантирует доступ к Codex или совместимость с конкретной версией сервиса.
- В карточке аккаунта показан срок access token из JWT; непрозрачные токены имеют неизвестный срок. Это метаданные, а не криптографическая проверка. Истёкшие токены пропускаются в JSON, исходный текстовый формат сохраняется с предупреждением.
- Обычные проверки выполняются одной очередью: повторные запросы одного аккаунта объединяются, новые добавляются последовательно. Максимум256 ожидающих; ручной этап сохраняет очередь до «Продолжить». Только чтение метаданных повторяется при временных сетевых/429/5xx ошибках, максимум три попытки с задержкой; формы входа не переотправляются.
- Удаление аккаунта или группы переносит записи в «Корзину». Восстановление сохраняет доступы и профиль браузера и не перезаписывает конфликтующие аккаунты. «Удалить навсегда» окончательно удаляет только выбранную запись корзины после отдельного подтверждения. Корзина хранится в том же защищённом правами файле0600; история удалений до этого обновления не создаётся автоматически.
- `Сменить доступы → 2FA` для одного аккаунта выполняет полный проверяемый цикл: старый секрет заменяется лишь после чистого входа с новым секретом, а проверенная сессия сохраняется.
- Если новый authenticator пришлось подключить вручную, вставьте его Base32-ключ в аварийное поле `Новый 2FA уже подключён вручную?`: приложение сначала проверит чистый вход и только затем заменит сохранённый ключ.
- Смена доступов в группе выполняется строго по одному аккаунту. Следующий начинается только после успешного завершения текущего. При ошибке или ручной проверке вся очередь ждёт; «Продолжить смену доступов» продолжает этот же аккаунт, затем оставшиеся. «Остановить» отменяет оставшуюся очередь, сохраняя записанные этапы восстановления.
- CAPTCHA, неизвестные проверки и изменившиеся страницы ChatGPT требуют ручного действия во встроенном браузере.
- Перед удалением данных используйте экспорт.
- Не добавляйте реальные учётные данные в git, тесты, скриншоты или отчёты об ошибках.
- Локальная сборка использует ad hoc подпись или доступный сертификат Apple Development. Для распространения подписанных сборок за пределами Mac App Store нужны Developer ID и нотарификация.

Проверка получает срок и признак продления подписки через авторизованный запрос в текущей сессии. Если API не вернул дату, приложение пробует карточку текущего тарифа. Это также работает с новым интерфейсом ChatGPT, где карточка тарифа больше не показывает срок. В Security распознаются оба названия: «Приложение-аутентификатор» и «Приложение для аутентификации».

Для запуска тестов в текущем Command Line Tools используется:

```bash
./script/test.sh
```

Если установленный Command Line Tools с SDK 27 выдаёт `Unknown error parsing property list` или не находит `SwiftUIMacros`, при наличии SDK 26.5 можно собрать так:

```bash
./script/test.sh --build-system native --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
./script/build_and_run.sh --verify --build-system native --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
```

### Восстановление зависшей страницы

Если временный браузер смены 2FA не получил первую страницу, приложение один раз пересоздаёт его соединение и повторяет загрузку, перенося cookies. Это работает только до появления первого документа: открытые формы входа, CAPTCHA и подтверждения не перезапускаются. Постоянные профили аккаунтов сохраняются. Если повторная попытка тоже не получила ответ, операция переходит к ручному восстановлению, сохраняя текущий этап и ожидающий ключ.

Для проверочного входа после включения нового 2FA предусмотрены до трёх попыток загрузить первый документ по 10 секунд, с новым соединением между попытками. Вход начинается сразу после появления документа, не дожидаясь зависших вспомогательных запросов. Над браузером отображается текущий шаг проверки нового ключа; отправка кода сама по себе ещё не означает успешный вход.

Если страница входа или Security перестала загружать нужные элементы, дождитесь ручного состояния операции. «Обновить страницу» и «Открыть раздел заново» сохраняют текущую сессию. «Новый вход» создаёт отдельную сессию; после возможного отключения старого 2FA приложение не отправляет старый код автоматически. Для стадии «Ожидается чистый вход» новая сессия использует только ожидающий ключ. Пока новая сессия не подтверждена для выбранного аккаунта, можно вернуться в исходную. Во время восстановления другие действия запуска недоступны.

## Регистрация нового аккаунта

Кнопка **Новая регистрация** открывает сценарий внутри GPT Account Manager.
Укажите email или выберите свободный адрес из базы и нажмите **Начать**. Имя и
возраст 21–45 генерируются случайно один раз при запуске каждой новой регистрации.
Отдельных полей профиля и галочек нет; условия указаны рядом с кнопкой запуска.

Приложение использует уже подключённый Mail.ru, получает только новое письмо OpenAI
для выбранного адреса, устанавливает пароль, заполняет профиль, подключает приложение-
аутентификатор, подтверждает его включение и сохраняет текущую сессию без повторного входа. После настройки
аккаунт сохраняется в **new-novoreg**, а его основная сессия остаётся в отдельном
постоянном браузерном хранилище приложения. Копирование cookies между приложениями
для этого сценария не требуется.

До успешной проверки запись остаётся черновиком регистрации и не считается готовой.
Ключ 2FA сохраняется до его подтверждения на сайте. **Остановить** сохраняет этап;
**Возобновить** возвращает к явно остановленному или завершившемуся ошибкой
сценарию; профиль и пароль сохраняются. Обычные переходы и загрузка страниц
продолжаются автоматически. Если OpenAI требует CAPTCHA, выполните её в открытой
странице: программа дождётся изменения и продолжит без дополнительной кнопки.
Неизвестная форма или окончательная ошибка сохраняет черновик для восстановления.
Новая регистрация и остальные операции не выполняются одновременно.

При регистрации отдельный проверочный вход не выполняется: после подключения 2FA
сохраняются текущая сессия и accessToken с проверкой совпадения почты и включённого аутентификатора.
Для уже существующего аккаунта используйте обычный импорт; регистрация не меняет
пароль и 2FA существующего аккаунта.

## Прокси

В разделе **Прокси** включается случайный выбор доступного адреса для регистрации.
Выбранный прокси закрепляется за аккаунтом и используется его браузерными сессиями.
Список и ссылки-источники можно добавлять, редактировать и удалять; проверки
показывают задержку и внешний IP. Если рабочий адрес не найден, программа не
подменяет прокси прямым соединением. По умолчанию режим выключен.
Поддерживается авторизация: `host:port:login:password` (HTTP) или
`protocol://login:password@host:port` для HTTP, HTTPS и SOCKS5.

Подробнее: [docs/PROXIES.md](docs/PROXIES.md).

Если закреплённый прокси недоступен, перед проверкой аккаунта или возобновлением
регистрации подбирается другой рабочий. В карточке и у остановленной регистрации
доступна кнопка **Сменить прокси**. Сессия, данные и группа аккаунта сохраняются.
